# Comentarios en código

- Comentarios acotados, no excesivos: solo cuando el *por qué* no es obvio leyendo el código (una decisión no evidente, una restricción externa, un workaround puntual).
- No comentar el *qué* hace el código si ya se entiende por nombres de variables/funciones.
- No dejar comentarios de bitácora en el código (eso va en `specs/<ticket>/notes.md`), ni comentarios de código muerto.
